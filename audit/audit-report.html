Fine Print Fighter — use cases, holes, and next work

Audit of the current working tree on branch main. Scope: product surface, backend/API, AI pipeline and evidence handling, frontend/UX, tests, and documentation. No files were changed.

1. Product and use cases

Consumer dispute intake

Select one of three packs (flight delay/cancellation, subscription cancellation, surprise bill/fee) and one of three jurisdictions (IN, EU, US). Paste or upload document text plus the company’s actual reply. Optional name, desired outcome, language, reply period.

Grounded analysis

Extracts document facts, plans bounded research queries, searches Tavily, evaluates findings for and against the consumer, verifies exact passages, scores evidence coverage, and produces an editable cited letter.

Rebuttal Lab

Investigates the company’s possible defenses, identifies missing exhibits, supports up to three separately identified exhibits, and re-runs analysis when evidence is supplied. Shows before/after comparison.

Evidence walkthrough

Offline fictional sample built on the same exact-passage matcher, with remove/irrelevant/restore/edit states. No model or research calls.

Letter export

Controlled editor; download current text plus sources; print letter and sources only. No automatic sending or filing.

Saved private cases

Supabase-backed accounts, RLS-scoped case storage, reanalysis, export, and account deletion. Guest analysis remains transient.

Content and coverage pages

Company directory (Air India, Netflix), practical guides, complaint category pages, jurisdiction and coverage notes.

Escalation guidance

Jurisdiction-specific escalation lists, explicitly labeled unreviewed, with no verified contacts or deadlines.

2. Strengths worth preserving

  • Evidence discipline: stable source IDs, exact-passage verification, application-checked references, opposing findings preserved, applicability kept explicit.
  • Safety: provider errors do not leak upstream bodies; safe public error messages; no client-supplied verification flags; search queries minimized through safeSearchEntity.
  • Bounded AI behavior: initial attempt plus one repair, no recursive repair, 25s model timeout, 15s research timeout, 120s overall deadline.
  • Rate limiting: shared Upstash rolling IP/global budget, HMACed IP identifiers, process-local concurrency cap, development budget.
  • Letter integrity: deterministic English template, quoted source passages, application-allocated citation markers, placeholders for missing details.
  • UX trust signals: fictional-sample disclosure, model attribution, evidence coverage status, limitations section, no outcome prediction.

6. Test and documentation debt

  • Coverage gaps: no tests for catalog.ts, saved-cases.ts, shared-budget.ts, rebuttal.ts, Supabase helpers, saved-case/account routes, stage-api plan/evaluate/draft branches, llmToolTurn, NDJSON/budget/active-analysis behavior, and component flows.
  • Docs drift: README says no application database/saved case history; implementation says no database; deployment omits Supabase env vars; privacy wording overstates retention for saved cases.
  • Counts: implementation docs say 45 tests; suite now has 49 test cases.
  • Spec scope: spec describes storage as transient/no database and accounts/persistence as outside MVP; update to reflect saved cases or mark as documented post-MVP extension.

7. Suggested feature additions

Trustworthy pipeline fixes

Make numeric grounding sign-aware; fix citation allocation; add applicability review or document the intentional ceiling; improve PII filtering; validate HTTPS sources.

Compensation engine

Implement reviewed, testable monetary formulas with currency, source ID, inputs, assumptions, and working. Keep disputed charge separate from entitlement.

Multilingual letters

Add and evaluate additional letter language templates; current template is English only.

More packs and jurisdictions

Add pack version review dates, preferred-domain ranking, typed extraction fields, sector/route applicability facts, and additional jurisdiction selectors.

Saved-case UX

Pagination, search/filter, reanalysis progress, export, profile editing, and clearer saved-case privacy messaging.

Observability

Stage durations, provider status, counts, request IDs, safe logging; deployment deadline checks; measured latency and failure reporting.

Accessibility

Loading states, session-aware header, error boundaries, keyboard focus, mobile print/export, and reduced-motion support.

Release gates

Live provider verification, 20+ representative runs, jurisdiction review, compensation formulas, retention review, and global cap from measured cost.

8. Recommended immediate sequence

  1. Fix build: resolve cacheComponents vs dynamic segment config and the lint error.
  2. Fix tests: add path alias, update stale request/pipeline fixtures, add rebuttal mock.
  3. Fix evidence bugs: sign-aware numeric grounding and citation allocation.
  4. Harden saved cases: UUID validation, body size caps, analysis validation, registered pack check.
  5. Update docs: README, implementation, deployment, spec to reflect saved cases and Supabase.
  6. Run npm run verify until green, then address medium-severity security and UX items.

Conclusion

The application has a strong evidence-first architecture and substantial safety work. The main release blockers are build/lint/test drift, a few concrete evidence-grounding bugs, and documentation that no longer matches the implemented saved-case/account features. Addressing the high-severity items first should restore a green verification pipeline without changing product scope.
