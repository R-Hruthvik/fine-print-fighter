User-end experience audit

From opening the app to using the result

Read-only analysis of the real user journey, provider/configuration friction, and how clearly the app answers user questions.

1. Journey overview

  1. Home (`src/app/page.tsx`): long, content-heavy; primary CTA “Start a complaint” → `/complaints/new`.
  2. Intake stage 1 (`FighterApp.tsx:283-292`): company (optional, only 2 suggestions), jurisdiction, complaint type.
  3. Intake stage 2 (`FighterApp.tsx:293-305`): document text required; upload `.txt/.md` only; company response required.
  4. Intake stage 3 (`FighterApp.tsx:306-311`): summary, privacy note, “Analyze my case.”
  5. Analysis (`submitAnalysis`): streaming progress, 125s client timeout, cancel support.
  6. Results (`CaseResult.tsx`): strength, Rebuttal Lab, limitations, facts, findings, remedy, letter, escalation, sources.
  7. Saved cases (`/cases`, `/cases/[caseId]`): optional account save, static snapshot, reanalysis.

5. Dead ends and missing guidance

  • No path for users without a company response.
  • No PDF/image ingestion; only `.txt/.md`.
  • No autosave/draft persistence.
  • No PII-redaction prompt in intake.
  • Saved-case reanalysis has no progress/cancel and cannot incorporate new exhibits.
  • Header lacks authenticated state; “My cases” sends guests to a sign-in wall.
  • No retry affordances or countdown after rate limits.
  • No configuration preflight/status indicator.

6. Recommended UX improvements

  • Make company response optional with a “summarize the company’s reply” fallback, or clearly state it is required before analysis.
  • Add autosave/draft persistence and a PII-redaction reminder.
  • Provide plain-language definitions for key terms (source-backed, applicability, coverage, exhibit).
  • Reconcile citation IDs between findings and letter.
  • Add retry/backoff and countdown for rate limits and timeouts.
  • Add a configuration preflight check and clearer operator guidance.
  • Make saved-case reanalysis show progress and allow exhibit updates.
  • Make the header session-aware.
  • Validate letter placeholders before download/print.
  • Reduce jargon in results and provide a “what this means” summary.
